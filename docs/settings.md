# 设置说明

> 这篇是 WebUI「设置」页的逐项说明。第一次部署先看[使用指南](guide.md)；插件自己的设置看对应插件文档。
>
> 设置页写入 `config/config.toml`。点「保存」才落盘；标「需重启」的项要重启进程。直接改配置文件也可以，但注释会被保留，重启后生效。

## 1. 先理解三件事

1. **配置只有一个来源**：`config/config.toml`。WebUI 只是读写它，不是另一份配置。
2. **保存不是自动的**：改完点「保存」；「放弃改动」恢复上次保存的值。
3. **动态内容不进 system**：时间、群名、说话人、插件注入都在当前 user 消息里。这是为了 KV 缓存，不要试图把这些挪回 system。

## 2. 服务与访问

| 设置 | 默认 | 说明 |
|---|---|---|
| 监听地址 `server.host` | `127.0.0.1` | FastAPI 监听地址。只在本机用就保持；要让别的机器连，改成 `0.0.0.0` 并自己处理防火墙。改完需重启 |
| 监听端口 `server.port` | `8790` | WebUI、健康检查、OneBot 反向 WS 共用这个端口。改完需重启，SnowLuma 的 URL 也要跟着改 |
| 日志级别 `server.log_level` | `info` | `debug` 排查用；`info` 日常；`warning`/`error` 更安静 |
| 状态行间隔 `server.status_interval` | `300` | 控制台每隔多少秒打一行「在线时长 / 收发条数 / 首字均值」；`0` 关闭。改完需重启 |

## 3. OneBot 连接

| 设置 | 默认 | 说明 |
|---|---|---|
| WS 路径 `onebot.path` | `/onebot/v11/ws` | SnowLuma 反向连进来的路径。完整地址是 `ws://127.0.0.1:8790` + 这个路径 |
| 鉴权 token `onebot.access_token` | 示例值 | 必须和 SnowLuma 的 `accessToken` 完全一致；留空 = 不校验。改完需重启 |
| 动作超时 `onebot.action_timeout` | `15.0` | 等 `send_group_msg`、`get_msg` 等 OneBot action 回执的秒数 |
| 最大连接数 `onebot.max_connections` | `1` | 只允许一个 QQ 端连着。多开会重复收消息、重复回复。改完需重启 |

## 4. 模型

这一页分成「模型配置」和「连接」两块。模型配置是 `config/models.toml` 里的 profile；「连接」是当前 profile 的字段。

### 4.1 模型配置卡

- **默认**：内置 profile，修改后保存到 `config/models.toml`。
- **切换**：点卡片切换当前 profile；页头会显示「当前」。
- **新建**：输入名字回车；重名/空名会行内标红，不会静默失败。
- **排序**：拖动卡片或点「排序」。
- **删除**：卡片右侧 ×；至少保留一个。

### 4.2 连接

| 设置 | 默认 | 说明 |
|---|---|---|
| 接口地址 `llm.base_url` | `http://127.0.0.1:1234/v1` | LM Studio 的 OpenAI 兼容端点。保存时会重建客户端，不用重启 |
| API Key `llm.api_key` | `lm-studio` | LM Studio 不校验，填什么都行；不要提交真实云端 key |
| 模型标识 `llm.model` | `qwen3.8-27b` | 必须和 LM Studio 当前加载的模型 id 完全一致；可点「获取模型」选择 |
| 最大上下文 `llm.max_context` | `0` | `0` = 不额外限制。填了就取它的 50% 作为 prompt 预算上限，防止 prompt 撑爆窗口 |
| temperature | 留空 | 留空 = 不发送，用 LM Studio/模型模板自己的值；想固定就填 0~2 |
| top_p | 留空 | 留空 = 不发送；与 temperature 二选一调即可 |
| max_tokens | `0` | `0` = 不发送，让模型自己收尾。设太小会把思考吃光，正文变空 |
| 思考档位 `reasoning_effort` | 留空 | `none`/`low`/`medium`/`high`；留空 = 不发送。现在主要靠人设篇幅约束 |
| 流式返回 `stream` | `false` | 关掉 = 整段生成完再发；打开首字更早，但工具调用仍走非流式。非流式下思考量上限无效 |
| 思考量上限 `thinking_budget` | `0` | 客户端保险丝：边收边数思考 token，超了掐断换无思考重答；`0` 关闭，只在流式下有效 |
| 请求超时 `timeout` | `120` | 等模型首个响应的上限（秒） |
| 并发请求上限 `max_concurrency` | `4` | 对应 LM Studio 的并行槽位数。同一会话永远串行；多个群同时聊会互相抢显存和缓存 |
| presence_penalty | `0` | `0` = 不发送；正值鼓励新话题，负值鼓励重复 |
| frequency_penalty | `0` | `0` = 不发送；正值降低重复词 |

> 模型越大、思考越多、并发越高，首字越慢。先保证单会话可用，再考虑并发。

## 5. 上下文

| 设置 | 默认 | 说明 |
|---|---|---|
| 接过的消息条数 `context.max_messages` | `40` | 只统计 bot 接过的问答轮次，一问一答算 2 条；40 条约 20 轮。锚点窗口在 100%~125% 浮动，超过 125% 才回落 |
| token 预算 `context.max_tokens` | `6000` | 估算预算。超了从最旧丢，且一次退到 60%，避免每轮都移动前缀；图片和 ambient 另占预算 |
| 只记被接过的轮次 `only_addressed` | `true` | 群里跟它无关的闲话不进持久历史，只额外保留最后一段没回的；关掉会明显变慢、也更容易算错人 |
| 包含自己的回复 `include_bot_replies` | `true` | 关掉后历史里没有 assistant 消息，模型只能看到用户侧 |
| 合并连续同角色 `merge_same_role` | `true` | 只合并回给同一个人的连续 assistant；user 一律独立 |
| 历史行加时间戳 `timestamps` | `true` | 历史行前加 `[HH:MM]`，模型才能判断“刚才/两小时前” |

上下文不是越大越好。窗口拉大，思考量和注意力都会变差；长期记忆用 BOT空间，不要硬堆历史。

## 6. 人设

- **人设列表**：每张卡是一份 `personas/*.md`；点卡片切换当前人设，拖动/「排序」调整顺序，新建/删除同理。
- **兜底昵称 `persona.nickname`**：拿不到群名片时用它识别“叫到我”；默认 `小鲸鱼`。
- **人设正文**：Markdown。改完点「保存人设」即时生效，**不用重启**。篇幅、语气、是否用标点都会直接影响回复长度和思考量。

人设是外部 Markdown，不要把它当成代码；保存失败会行内提示，不会覆盖原文件。

## 7. 触发规则

| 设置 | 默认 | 说明 |
|---|---|---|
| 私聊必回 `trigger.private_always` | `true` | 私聊每条都回；关掉后私聊也要满足其他触发条件 |
| 被 @ 时回复 `trigger.group_at` | `true` | 群里被 @ 才回。默认关闭“每条都回” |
| 指令前缀 `trigger.group_prefix` | 空 | 例如填 `/`，群消息以 `/` 开头就触发；留空 = 不启用 |
| 关键词 `trigger.group_keywords` | `[]` | 逗号分隔；命中任意一个就回；留空 = 不启用 |
| 冷却 `trigger.cooldown` | `0` | 同一会话两次回复的最小间隔（秒）；`0` = 不冷却 |

引用机器人消息也会触发，这是 `reply` 语义的一部分，不受这里开关影响。

## 8. 回复方式

| 设置 | 默认 | 说明 |
|---|---|---|
| 引用回复 `reply.quote` | `true` | 回复时带 OneBot reply 段，引用触发消息 |
| @ 被回复的人 `reply.at_sender` | `false` | 群里每条都 @ 会刷屏；默认靠引用表明在回谁 |
| 长回复分段 `reply.segments` | `true` | 长回复按句读/换行切成多条发，模拟真人连发 |
| 最多几段 `reply.max_segments` | `4` | 分段上限；短回复通常只有 1 段 |
| 每段字数 `reply.segment_max_chars` | `120` | 超过这个长度才退到空格/逗号切；不是每句都切 |
| 分段间隔 `reply.segment_interval` | `0.6` | 两条之间的停顿（秒）；`0` = 连发 |
| 把 at 昵称变成真 @ `reply.resolve_mentions` | `true` | 模型写「at 昵称」时查群名片换成真正的 at 段 |
| 单条最多 @ 几个 `reply.max_mentions` | `3` | 防止模型一次 @ 太多人 |
| 去重窗口 `reply.dedupe_window` | `30` | 同一会话内相同内容在这段时间不重复发；`0` = 不去重 |

分段只对**长回复**有意义。短回复没有标点/换行时，就是一条。

## 9. 图片

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用识图 `images.enabled` | `true` | 关掉后不下载、不送图 |
| 单条最多几张 `images.max_per_message` | `2` | 一条消息最多处理几张图 |
| 单张大小上限 `images.max_bytes` | `20,000,000` 字节 | 面板按 **KB** 显示（默认 `19531.25KB`）；配置文件仍按字节存。1MB = 1024KB |
| 最长边像素 `images.max_side` | `512` | 缩到最长边不超过该像素再送模型；截图/带字图建议 768~1024 |
| 历史里额外带几张 `images.history_images` | `2` | `0` = 只处理当前这条；多带图会增加 token 和前缀抖动 |
| 下载超时 `images.timeout` | `15` | 下载 QQ 图片的超时秒数；改完需重启 |
| 下载走系统代理 `images.trust_env` | `false` | QQ 图床必须走代理才下得动时打开；改完需重启 |

## 10. 插件

- **启用/停用**：卡片右上角开关；新装 ZIP 默认启用。
- **安装 ZIP**：支持 `<插件id>/plugin.toml` 或根目录 `plugin.toml`；装完默认启用，加载失败会显示 `last_error`。
- **搜索/排序/分页**：按名称、ID、说明搜索；可按名称、安装时间、启用优先排序；每页 6 张。
- **设置**：插件自己的 `plugin.toml` 字段；说明见插件文档，不在主设置里重复。
- **文档**：打开插件 README；两个内置插件的完整说明也在主面板「文档」页签的「内置插件」。
- **打开面板**：未启用时只提示先打开开关，不跳空白页。
- **重载**：重跑 `setup()`；router 增删仍需重启进程。
- **删除**：可选保留/连 `data/plugin_data/<id>/` 一起删，删除不可恢复。

## 11. 配置文件里有、但 WebUI 没单独放的项

| 项 | 默认 | 说明 |
|---|---|---|
| `[extensions] dirs` | `[]` | 兼容外部插件目录；正常保持空，插件放项目内 `plugins/` |
| `[commands] prefix` | `/` | 用户命令前缀；命中命令不进模型、不进历史 |
| `[commands] admins` | `[]` | 能使用管理员命令的 QQ 号；留空 = 不限制 |
| `[commands] timeout` | `20` | 单条命令执行上限（秒） |
| `[persona] file` | 人设路径 | 当前人设；一般通过人设页切换，不用手改 |
| `[persona] order` | 列表 | 人设卡顺序；通过人设页拖动保存 |
| `[llm] extra_body` | `{}` | 原样并入请求体的高级字段；普通用户不要动 |

## 12. 保存与重启

- **不用重启**：模型连接、上下文、触发、回复、图片开关、人设正文、插件设置。
- **需要重启**：监听地址/端口、OneBot 路径/token/连接数、状态行间隔、图片下载超时/代理。
- 保存后顶部会列出需要重启的项；重启后再看日志确认。
