# 内置插件协作约定

> 这份文档给两个内置插件的 Agent 和主项目 Agent 共用。
> 目的不是限制插件开发，而是让“主项目宿主”和“插件面板”不各做一套。

## 1. 两个仓库的关系

```text
插件项目（主要开发）         主项目（分发与学习副本）
D:\Dev\whale_lexicon   →   plugins/whale_lexicon/
D:\Dev\bot_space       →   plugins/bot_space/
```

- **插件的主要开发在插件项目里**：源码、测试、版本、CHANGELOG 先在自己的仓库完成。
- 主项目 `plugins/<id>/` 是**完整内置副本**（运行时 + tests + docs），随 main 一起分发，
  方便其他人直接学习和跑测试；它不是第二个开发源。
- 主项目负责宿主能力：消息链路、模型客户端、工具协议、插件加载、WebUI 外壳和共享 UI 组件。
- 插件负责插件自己的能力、数据、面板和文档。

## 2. 依赖方向

**能依赖主项目就依赖主项目。**

插件可以依赖：

- `app.sdk`（唯一允许 import 的宿主 SDK 入口）；
- `/static/basecoat.css`、`/static/theme.css`、`/static/style.css`；
- `/static/ui.js` 里的共享控件（如 `uiSelect`）；
- `docs/plugin.md` 的 `api=2` 契约；
- `docs/ui-spec.md` 的界面骨架。

插件不要：

- 复制或改写主项目的设计令牌、按钮、设置行、弹窗、通知、下拉框；
- 自己发明一套并行组件库；
- 把主项目的 `app/web/static/*` 拷贝进插件目录；
- 直接改主项目代码来补插件需求。

如果宿主缺少一个可复用能力，按“宿主请求”处理，不要在插件里静默造一个平行实现。

## 3. UI 的边界

插件 `pages/index.html` 是**主面板里的插件页面**，不是独立应用。

- 顶栏、页头、页签、卡片、弹窗、Markdown 正文等骨架优先复用主项目类名。
- 插件页面可以有自己的布局/样式，但应使用 `theme.css` 的令牌，并注明哪些是插件特有布局。
- **弹窗退场动画属于宿主模式**：主项目已有 `.modal[open].is-closing` 和 `closeDialog`
  的退场时序。插件不要另起一套“独立前端”的动画系统；如果插件页面没有加载宿主
  `plugins.js`，先发宿主请求，要求主项目提供可复用的弹窗 helper（例如放进 `ui.js`）。
  在 helper 落地前，插件里的临时本地实现必须标注为 `host-gap`，并在交接里说明。
- 插件的局部覆盖只写插件自己的类，不要重定义 `.tabbtn`、`.modal`、`.toast` 等宿主类。

## 4. 谁能改什么

| 改动 | 谁做 |
|---|---|
| 插件业务、工具、存储、插件面板局部布局 | 插件 Agent |
| 插件 README / docs / tests / CHANGELOG / 版本 | 插件 Agent |
| 主项目 `plugins/<id>/` 副本同步 | 插件 Agent 完成后同步，或主项目 Agent 按插件提交同步 |
| `app/`、宿主 API、`app/web/static/style.css`、`ui.js`、共享组件 | 主项目 Agent |
| 主项目文档、WebUI 设置页、文档页签 | 主项目 Agent |
| 宿主缺少的能力 | 插件 Agent 提“宿主请求”，主项目 Agent 实现 |

**插件 Agent 不改主项目。** 主项目 Agent 也不在插件项目里做业务开发，除非用户明确要求。

## 5. 沟通协议（重要）

不同工作区没有消息总线，用户是当前的“通信总线”。每次插件要动 UI 或发现宿主缺口，按这个格式给用户一段交接，用户转给主项目：

```text
【插件】whale_lexicon / bot_space
【改动】一句话说明
【位置】插件项目文件 + 是否会同步到主项目 plugins/<id>/
【为什么不能只靠主项目】具体缺口（没有这个 helper / 这个类名不适用 / 需要新 API）
【是否碰主项目】否
【需要主项目做什么】一句话；没有就写“无”
【验证】测试/截图/手动路径
```

主项目 Agent 收到后：

1. 判断是插件局部问题还是宿主缺口；
2. 宿主缺口写进主项目文档/实现，并回复插件 Agent；
3. 不需要宿主改的，明确说“插件内解决”；
4. 不把插件的临时 workaround 当成主项目契约。

## 6. 当前已定的规则

- 两个插件是**内置插件**：主项目默认启用，`config.example.toml` 里
  `enabled = ["bot_space", "whale_lexicon"]`。
- 当前发版：鲸语汇 `0.6.0`（`api=1`）、鲸鱼空间 `0.5.5`（`api=2`）。
- 弹窗退场 helper 还没从主面板 `plugins.js` 抽到 `ui.js`；两个插件当前的本地
  `closeMask` 标成 `host-gap`，复用宿主 `.modal[open].is-closing` 和 330ms 兜底。
  下一版主项目把通用 helper 放进 `ui.js` 后，插件再删本地时序。
- 插件开发以插件项目为主；主项目副本包含完整 tests/docs，用于分发和学习。
- **鲸鱼空间主旨**：bot 的私人 Markdown 空间，用户只读；模型用 `space_*` 工具自己决定读写，
  不提供用户 `/space` 命令；全局一份，不分群聊私聊；删除/修改走预览确认，不是硬 ACL。
- **鲸语汇主旨**：群黑话自学习；模型提取 + 自审；按群隔离；命中注入；数据在
  `data/plugin_data/whale_lexicon/`。
- 工具对所有会话暴露，`is_group` 只作为元数据，不做权限分流。
- 面板小字要简洁、准确；能靠宿主组件表达的，不重复造。

## 7. 交接检查表

- [ ] 插件测试通过（`pytest plugins/<id>/tests -q`）
- [ ] 插件自检通过（`python -m app.pluginkit.check plugins/<id>`）
- [ ] 没直接改主项目；如果改了，已回滚并改为宿主请求
- [ ] 插件面板复用了宿主 CSS/UI 组件；局部覆盖有注释
- [ ] 交接里写清是否同步主项目副本
- [ ] 主项目文档需要更新的地方已列出
